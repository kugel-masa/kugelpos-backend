# カートスナップショット署名鍵のローテーション手順

対象: cart サービスの署名付きカートスナップショット（issue #148 / spec `specs/148-cart-snapshot-restore/`、および issue #156 / spec `specs/156-stateless-cart/`）の HMAC 鍵運用。

> phase 2（#156）でスナップショットの提示経路が変わった。restore API は撤去され、**変更系リクエストが毎回スナップショットを同梱**する方式に一本化されている。鍵の役割と運用手順は変わらないが、本書の「restore」はすべて**「同梱されたスナップショットの検証」**を指す。

## 前提

- 鍵は環境変数 `SNAPSHOT_HMAC_KEYS` で配布する。形式は `"<kid>:<base64鍵>[,<kid>:<base64鍵>]"`。
  - **先頭のエントリが現行鍵**（署名に使用）。2 つ目以降は**前世代鍵**（検証のみ受け入れ）。
- 鍵はフェイルオーバー網に参加する**全バックエンド（エッジ/クラウド）で同一の値**を設定する。片側だけ更新すると、未更新側で発行されたスナップショットが更新側で検証できなくなる。
- JWT の `SECRET_KEY` とは**別の鍵**を使う（用途別の鍵分離。流用禁止）。
- 未設定の場合、機能は縮退する: スナップショットは発行されず（レスポンスの `signedSnapshot` が null）、提示されたエンベロープは全て拒否される。起動ログに warning が出る。
  **縮退はエラーを返さない**。クライアントはサーバ側カートキャッシュ経路（DUAL モード）に無言でフォールバックするため、本番環境では必ず設定すること。

## 鍵の生成

```bash
openssl rand -base64 32      # 256bit 鍵
```

kid は世代が分かる短い識別子（例: `v1`, `v2`, `2026q3`）。

## 通常ローテーション（無停止）

スナップショットの実効寿命は「進行中取引の最大寿命」（端末トークン寿命 24h に整合）。**前世代鍵の受け入れ猶予を 24 時間以上**確保する。

1. 新鍵を生成し、新しい kid を割り当てる（例: `v2`）。
2. **全バックエンド**の `SNAPSHOT_HMAC_KEYS` を更新する: `"v2:<新鍵>,v1:<旧鍵>"`（新鍵が先頭 = 署名は即 v2 に切替、v1 は検証のみ）。サービスを再起動（またはローリング再起動）。
3. POS が保持する旧鍵署名スナップショットは、猶予期間中も受け入れられる（kid=v1 で検証）。
4. **24 時間以上経過後**、`SNAPSHOT_HMAC_KEYS="v2:<新鍵>"` に縮めて旧鍵を削除し、再起動。
5. 以降、kid=v1 のスナップショットは `401503`（未知の鍵 ID）で拒否される。拒否は `log_cart_restore` とアプリログ（warning）に記録される。

ステップ 2〜4 の間に全バックエンドの値が揃っていない時間帯を作らないこと（更新は揃えて行う）。

## 緊急ローテーション（鍵漏洩時）

漏洩した鍵で署名された「正当に見える」スナップショットの注入を止めることを最優先とする。

1. 新鍵を生成し、**旧鍵を含めず** `SNAPSHOT_HMAC_KEYS="v3:<新鍵>"` として全バックエンドへ即時配布・再起動する。
2. **トレードオフ（仕様上の明示事項）**: この時点で POS が保持している旧鍵署名スナップショットは全て無効化され、進行中取引の復元コピーが失われる。DUAL モードで運用している間はサーバ側キャッシュ（Redis/MongoDB）が生きていれば取引を継続できるが、`CART_REQUEST_SNAPSHOT_MODE=REQUIRED` に切り替えた後、あるいはキャッシュも失われている場合は**再入力となる**。
3. 漏洩鍵で署名されたスナップショットの提示は `401503` で拒否され続ける。`log_cart_restore` の `rejected`（reject_reason=401503/401501）を監視し、攻撃の痕跡を確認する。`api_path` フィールドにどの API に対する提示だったかが記録される。

## 監視ポイント

- 起動ログ: `Snapshot signing keys loaded: kids=[...]`（鍵ロード成功）/ `SNAPSHOT_HMAC_KEYS is not set`（縮退）/ `malformed`（設定ミス）。
- **起動ログ（ERROR）: `SNAPSHOT_HMAC_KEYS contains key material published in this repository`**。開発用 compose の既定鍵（`dev-v1:...`）やテスト鍵が本番に紛れ込んだ場合に出る。この鍵は公開されているため、**署名は実質的に無効**（任意の金額のカートを誰でも署名できる）。検知したら緊急ローテーション手順で即時交換すること。
- 検証失敗はセキュリティイベントとして warning ログ + `log_cart_restore`（`result=rejected`）に記録される。`cart_id` で全履歴を追跡できる。
- スナップショットの raw サイズが `SNAPSHOT_SIZE_WARN_BYTES`（既定 256KB）を超えると warning が出る（サイズ予算 R-008 の見直しシグナル）。
