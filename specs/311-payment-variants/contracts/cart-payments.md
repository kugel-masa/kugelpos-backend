# Contract: cart の支払の登録・取消・返品と支払行

JSON は camelCase。

---

## 支払の要求（3 つの端点で共用）

- `POST /api/v1/carts/{cart_id}/payments`
- `POST /api/v1/tenants/{tenant_id}/stores/{store_code}/terminals/{terminal_no}/transactions/{transaction_no}/void`
- `POST /api/v1/tenants/{tenant_id}/stores/{store_code}/terminals/{terminal_no}/transactions/{transaction_no}/return`

要求の本体は支払の配列（既存）。各要素に任意の `variantCode` が加わる。

```json
[
  {"paymentCode": "11", "amount": 2000, "detail": null, "variantCode": "PAYPAY"}
]
```

スナップショット・確定の文脈（#156）の持ち回りは既存のまま。

---

## 支払の登録

サブコードの決定（spec FR-012・FR-013）:

| 支払方法の有効なサブコード | `variantCode` あり | `variantCode` なし |
|---|---|---|
| 0 件 | 存在しない → 403018、停止中 → 403019 | サブコードなし |
| 1 件 | その支払方法の有効なサブコード → 採用。存在しない → 403018、停止中 → 403019 | その 1 件 |
| 2 件以上 | 同上 | 403020 |

- 「存在しない」は、別の支払方法にだけ存在する場合を含む
- 挙動（プラグイン・上限・超過預かり・釣銭）は支払方法で決まる（403004・403017 は現行どおり）
- サブコードの決定は、配列のすべての要素について支払プラグインを呼ぶ前に済ませる。どれか 1 つでもサブコードで拒否されれば、どの支払も記帳されない
- 拒否されたとき、カートは変わらない（配列の途中の要素で拒否されたら、要求全体が失敗し、カートは要求の前のまま。現行も最後に 1 回だけ保存する）

---

## 取消（void）

要求の各支払の鍵は「支払方法＋サブコード」（`variantCode` の省略は「サブコードなし」）。

- 鍵が売上時の支払行に無い → 拒否（現行の取消の照合と同じ 400）
- 鍵ごとの金額が売上時の合計と一致しない → 拒否（同上）
- 取消の支払行の名前・支払方法の名前は売上時の行から

例: 売上時が `11/VISA 1000`・`11/PAYPAY 2000` のとき

| 要求 | 結果 |
|---|---|
| `[{"paymentCode":"11","variantCode":"VISA","amount":1000},{"paymentCode":"11","variantCode":"PAYPAY","amount":2000}]` | 取消できる |
| `[{"paymentCode":"11","amount":3000}]` | 拒否（売上時に `11`・サブコードなしの行が無い） |
| `[{"paymentCode":"11","variantCode":"VISA","amount":3000}]` | 拒否（金額が一致しない） |
| `01`・`12`・`11/JCB` を含む | 拒否（売上時の支払種別ではない） |

サブコードの無い取引は現行の要求のまま取消できる。

---

## 返品（return）

要求の各支払（鍵は取消と同じ）:

| 要求の支払 | 扱い |
|---|---|
| 鍵が売上時の支払行にある | 受け付ける。名前は売上時の行から。現金以外は鍵ごとの返金額の合計が売上時の合計以下でなければ **403022** |
| 鍵が売上時に無いが支払コードが `01`（現金） | 受け付ける。サブコードは支払の登録と同じ規則（403018・403019・403020）、名前は現在のマスタ |
| それ以外 | **403021** |

- 売上時の行にあるサブコードは、停止中でも受け付ける
- 返金の合計が取引の合計と一致すること、返金可否・上限（403014・403015）は現行どおり

例: 売上時が `11/VISA 1000`・`11/PAYPAY 2000` のとき

| 要求 | 結果 |
|---|---|
| `11/PAYPAY 2000` + `01 1000` | 返品できる |
| `01 3000` | 返品できる |
| `11/VISA 3000` | 403022 |
| `11/JCB 1000` + … / `12 3000` | 403021 |

**既存動作の変更**: 現行は任意の支払方法で返金できる。売上時と違う支払方法（現金以外）での返品は 403021 で拒否されるようになる。

## 支払行の応答（カートの応答・取引の応答）

```json
{
  "paymentNo": 1,
  "paymentCode": "11",
  "paymentName": "PayPay",
  "paymentAmount": 2000.0,
  "paymentDetail": "no detail",
  "variantCode": "PAYPAY",
  "builtinPaymentName": "キャッシュレス"
}
```

- `paymentName`: 支払行の名前（サブコードで記帳した行はサブコードの名前）
- `variantCode`: サブコードなしは `null`
- `builtinPaymentName`: 販売時点の支払方法の名前。本フィーチャーの前の取引は `null`

---

## 新しいエラーコード

| コード | HTTP | 意味 |
|---|---|---|
| 403018 | 400 | 指定したサブコードがその支払方法に無い |
| 403019 | 400 | 指定したサブコードが停止中 |
| 403020 | 400 | サブコードの指定が要る |
| 403021 | 400 | 返品の支払種別が売上時の支払種別でも現金でもない |
| 403022 | 400 | 返品で売上時の支払種別に返す額が売上時の金額を超える |
