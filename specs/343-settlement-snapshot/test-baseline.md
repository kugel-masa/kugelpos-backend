## 理論在高の確かめ（追加、2026-11-24）

精算実績の理論在高が、在高を動かす取引の種類ごとに正しいかを、手で計算した値と比べて確かめた。

**report の統合テスト**（`tests/integration/test_settlement_cash.py`、実際の MongoDB）。どの場面でも、精算実績の理論在高・凍結した売上レポートの現金の欄・同じ営業の速報の現金の欄の 3 つが、手で計算した値と一致する。

| 場面 | 期待する理論在高 |
|---|---|
| お釣りが出る現金払い（220 の会計を 1,000 で受け取る） | 準備金 + 220 |
| 販売とその取消 | 準備金 + 0 |
| 返品（550 を現金で返金） | 準備金 + 1,100 − 550 |
| 返品の取消 | 準備金 + 1,100 |
| 現金とカードの分割（現金 1,000、カード 2,300） | 準備金 + 1,000 |
| カードのみ | 準備金 |
| 出金 2,000 と入金 300 | 準備金 + 1,100 − 2,000 + 300 |
| 会計前に取り消したカート | 準備金 + 1,100（取り消したカートは入らない） |
| 準備金なしで開設 | 1,100 |
| 上のすべてを 1 つの営業に混ぜ、数えた現金が 30 足りない | 内訳（入金・出金）と過不足 −30 も一致 |

**サービス横断の e2e**（`tests/e2e/test_settlement_cash_journey.py`、本物の cart と terminal）。1 つの営業で、お釣りの出る現金払い、現金とカードの分割、現金で返金した取消、現金で返金した返品、出金、入金を行い、cart が答えた会計の額から理論在高をテストの側で計算した。精算の応答、確定した精算実績（内訳を含む）、端末の日報の現金の欄が、すべてその値と一致し、数えた現金が 50 足りないときの過不足 −50 も一致した。
